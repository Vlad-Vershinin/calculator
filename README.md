# Калькулятор и каталог файлов

Веб-калькулятор с интерфейсом в стиле стандартного калькулятора Windows. Пользователь может набирать выражения из нескольких операций, использовать скобки и получать результат без полной перезагрузки страницы.

Примеры поддерживаемых выражений:

```text
1 + 2 + 4 = 7
2 + 3 × 4 = 14
(2 + 3) × 4 = 20
10 ÷ 2 − 3 = 2
```

## Стек

- **Next.js 16** — App Router, серверная страница и Server Action.
- **React 19** — клиентское состояние интерфейса и `useActionState`.
- **TypeScript 5** — типизация компонентов и серверной логики.
- **CSS Modules** — изолированные стили калькулятора.
- **ESLint 9** — статическая проверка кода.

## Принцип работы

В интерфейсе доступны два режима вычисления. Выражение и его результат отображаются на общей клавиатуре, а пользователь выбирает, где выполнять расчёт.

1. Страница `src/app/page.tsx` подключает интерактивный калькулятор.
2. Компонент `src/app/calculator.tsx` работает в браузере и хранит выражение в `useState`. Цифры и операции отображаются сразу.
3. В режиме «Клиентский» кнопка `=` вычисляет выражение непосредственно в браузере.
4. В режиме «Серверный» кнопка `=` отправляет форму в Server Action `calculate` из `src/app/actions.ts`; сервер возвращает результат или ошибку.
5. Оба режима используют общий рекурсивный парсер из `src/app/calculator-core.ts`. Он не использует `eval` и обрабатывает операции с правильным приоритетом:
   - сначала числа, скобки и унарные знаки;
   - затем умножение и деление;
   - затем сложение и вычитание.
6. После успешного вычисления исходный пример отображается мелким шрифтом над результатом.

Клиентский режим выполняет вычисления локально. Серверный режим передаёт вычисление серверу, не перезагружая всю страницу.

## Каталог файлов

Страница `/files` показывает файлы из каталога, заданного переменной окружения `DOWNLOAD_FILES_DIR`. По умолчанию используется `/var/www/calculator-files`. Ссылка «Файлы для скачивания» доступна на странице калькулятора.

Список строится на сервере при каждом запросе, поэтому новые файлы появляются после загрузки по FTP без пересборки приложения. Ссылка ведёт в Route Handler `src/app/api/files/route.ts`, который выдаёт содержимое как вложение. API принимает только имя одного файла из каталога; пути с каталогами, скрытые файлы и символьные ссылки отклоняются. Не помещайте в общий каталог секретные или личные данные: посетители страницы могут скачивать опубликованные там файлы.

Для локального запуска можно задать собственный каталог:

```bash
DOWNLOAD_FILES_DIR=./shared-files npm run dev
```

### Подключение каталога на сервере

Пример использует отдельную системную группу `filedrop`, чтобы FTP-пользователь мог загружать файлы, а служба Next.js — читать их:

```bash
groupadd --system filedrop
usermod -aG filedrop FTP_USER
install -d -o root -g filedrop -m 2770 /var/www/calculator-files
```

Замените `FTP_USER` на существующего локального FTP-пользователя. Настройте его FTP-корень (`local_root` в vsftpd) на `/var/www/calculator-files` и маску загрузки `local_umask=007`, чтобы файлы оставались доступными группе `filedrop`.

Добавьте переменную каталога и группу к systemd-службе:

```bash
mkdir -p /etc/systemd/system/calculator.service.d
cat > /etc/systemd/system/calculator.service.d/files.conf <<'EOF'
[Service]
Environment=DOWNLOAD_FILES_DIR=/var/www/calculator-files
SupplementaryGroups=filedrop
EOF

systemctl daemon-reload
systemctl restart calculator
```

### Nginx и материалы для отчёта

В `deploy/nginx-files.conf` находится пример отдельного Nginx server block на порту `5001`, проксирующего запросы в Next.js на `127.0.0.1:3000`. Его можно подключить так:

```bash
cp deploy/nginx-files.conf /etc/nginx/sites-available/calculator-files
ln -sfn /etc/nginx/sites-available/calculator-files /etc/nginx/sites-enabled/calculator-files
nginx -t && systemctl reload nginx
```

Текущая конфигурация Nginx, которая уже проксирует порт 80 на `127.0.0.1:3000`, тоже обслуживает `/files`; отдельный порт настраивать необязательно. Если используете порт `5001`, разрешите TCP `5001` в firewall сервера и панели хостинга.

После открытия `/files` и скачивания тестового файла снимите настоящие фрагменты для отчёта:

```bash
# Фрагмент лога с посещением каталога и скачиванием файла
sudo tail -n 30 /var/log/nginx/calculator-files.access.log

# Установленные TCP-соединения Nginx/Next.js (выполнять, пока идёт запрос)
sudo ss -tnp state established
```

Если отдельная конфигурация на порту `5001` не подключалась, access log обычно находится в `/var/log/nginx/access.log`.

## Структура проекта

```text
deploy/
└── nginx-files.conf            # пример Nginx-конфигурации и access log
src/
├── app/
│   ├── actions.ts              # серверная проверка, парсер и вычисление
│   ├── calculator.tsx          # интерактивная клавиатура и состояние ввода
│   ├── calculator-core.ts      # общий парсер выражений
│   ├── globals.css             # глобальные стили
│   ├── layout.tsx              # корневой макет
│   ├── page.tsx                # страница калькулятора
│   ├── page.module.css         # стили калькулятора
│   ├── files/
│   │   ├── page.tsx            # серверный список файлов
│   │   └── files.module.css    # стили списка файлов
│   └── api/files/route.ts      # потоковая выдача файла
└── lib/download-files.ts       # чтение и проверка файлов каталога
```

## Поддерживаемые возможности

- цифры от `0` до `9`;
- сложение, вычитание, умножение и деление;
- десятичные числа;
- круглые скобки;
- функции `sin`, `cos`, `tan`, `cot` в градусах или радианах;
- цепочки из нескольких операций;
- правильный математический приоритет операций;
- очистка выражения кнопкой `C`;
- удаление последнего символа кнопкой `⌫`;
- обработка деления на ноль и некорректных выражений.

## Запуск

Требуется Node.js 20 или новее.

Установка зависимостей:

```bash
npm install
```

Запуск в режиме разработки:

```bash
npm run dev
```

После запуска приложение доступно по адресу [http://localhost:3000](http://localhost:3000).

## Проверка и production-сборка

```bash
npm run lint
npm run build
npm run start
```

Команда `npm run start` запускается после успешного выполнения `npm run build`.
